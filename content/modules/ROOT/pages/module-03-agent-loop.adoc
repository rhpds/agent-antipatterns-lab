*Your read:* read `+run_agent+` in link:{lab-workbench-url}/agent/agent.py[`+agent.py+`^] and find two defects: one in what happens to a tool's result, and one in how the loop decides to stop.

====

[arabic]
. Neither the model's reply nor the tool result is added to `+messages+`, so every request carries only the system prompt and the question. The model never sees the result and asks for `+find_part+` again. The loop does record each result: `+runlog.add_tool_call+` saves it with the run, and the trace shows it in the tool's span. Those records are for you to read. Neither sends anything to the model.
. The loop decides it's done by checking whether the reply has tool calls, and whether its text contains the words "final answer". Nothing tells the model to write those words. The loop never reads `+finish_reason+`, the field where the model says why it stopped. If a reply ran out of tokens and was cut off (`+finish_reason+` is `+length+`), this loop would hand back the half-finished text as the answer.

Defect 1 causes the loop you saw. Defect 2 cost nothing in this run, because every reply asked for a tool. It shows up as soon as a reply is cut off.
