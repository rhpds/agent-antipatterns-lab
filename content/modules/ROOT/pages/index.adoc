= Four ways your agent can break

== Lab overview

You'll build a field service agent for Kestrel Industrial, a fictional maker of industrial cooling equipment. The agent helps service engineers find parts, check stock and delivery times, and look up service bulletins.

The agent you start with has problems that don't show up as errors. Module 1 shows you how to see inside it. In the modules after that, you find what's wrong from the evidence: the request sent to the model, the response that came back, what a tool returned, and the trace in MLflow. Then you apply the fix and check the evidence again.

== What's running in your lab

Everything runs on one OpenShift cluster with Red Hat OpenShift AI. Your workbench and database are in your own project. The model endpoints, MLflow and the tool gateway are shared by everyone in the session.

== How to work through the lab

Each module has a Jupyter notebook in your workbench. Open the *Notebook* tab on the right, where module 1's notebook opens. The first time, it asks you to log in. If it then shows "An authentication error occurred", click the refresh arrow next to the tab's name; you're already logged in, and the notebook opens. To open a later module, use the file browser on the left of JupyterLab: `agent-antipatterns-lab`, then `notebooks`. Run the cells in order. Questions marked *Your read* are for you to think about; you don't type an answer, and each has a collapsed block below it with the answer to check against. Each page on this side is a short guide to its module: what it covers, its steps, how you know it worked and, where the module has them, questions to think about. The code and its results are in the notebook.

Each notebook starts with a cell that puts the agent in that module's starting state. To start a module over, run that cell again. Your edits are saved in `agent/.reset-backup/` first.

Steps marked _stretch goal_ are optional. Skip them if you're short of time; nothing later depends on them.

The *>_ terminal* tab on the right is a separate command line, and the lab doesn't use it. Everything runs in the notebook.
