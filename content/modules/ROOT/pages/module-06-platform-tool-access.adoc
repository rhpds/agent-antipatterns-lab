== 2. Point the agent at the gateway

The lab's MCP Gateway serves the same tools from the platform. The lab runs MCP Gateway 0.7.1 (Technology Preview); version 1.0 is generally available in Red Hat Connectivity Link 1.5. Its address:

[source,python]
----
print(lab.gateway_url() or "This environment has no lab MCP Gateway (LAB_GATEWAY_URL isn't set).")
----

Open link:{lab-source-url}/agent/config.toml[`+config.toml+`], set `+gateway_url+` under `+[tools]+` to that address, and save. That's the only change to the agent. This cell confirms what it will use:

== 4. A new tool, without touching the agent

Ask the delivery question before anything changes. There's no delivery tool in the list above, so watch what the agent does without one:

[source,python]
----
if lab.config()["tools"].get("gateway_url"):
    lab.sh("python agent.py --q m6")
    lab.tool_results()
else:
    print("Set gateway_url first.")
----

Now register `+estimate_delivery+` at the gateway. It's a platform operation: one ConfigMap in your own project, which the lab's tool server reads. Nothing in the agent changes, and it isn't rebuilt or restarted. Only your catalog changes; other participants' don't.

[source,python]
----
lab.register_tool("estimate_delivery")
if lab.config()["tools"].get("gateway_url"):
    lab.tool_list()
----

Ask again:

[source,python]
----
if lab.config()["tools"].get("gateway_url"):
    lab.sh("python agent.py --q m6")
    lab.tool_results()
    lab.trace_link()
else:
    print("Set gateway_url first.")
----

*This is the module's success signal:* the agent discovered and used `+estimate_delivery+`, a tool it didn't have a moment ago, and answered "1 day". The tool catalogue is now a property of the platform, versioned and changed independently of the agent's releases.
