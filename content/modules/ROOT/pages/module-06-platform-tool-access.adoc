== If the result differs

.Open this if your result doesn't match what the notebook expects. It lists likely causes.
[%collapsible]
====

If the address cell in step 2 says this environment has no lab MCP Gateway, your workbench wasn't set up with one. You can't fix that from the notebook, so ask for help.

If the check in step 2 prints `+gateway_url: ''+`, `+config.toml+` isn't saved with the address. Save it and run that cell again. If the cell fails with an error about TOML, the address is missing its quotes. Until that check shows the address, the later cells say `+gateway_url+` isn't set and run nothing, and nothing gets registered.

If a run fails with HTTP 401 or 403, the gateway didn't accept the login your workbench sends. The notebook's steps use your workbench's own identity, not an admin login. That's an environment problem, not something in the agent, so ask for help.

Through the gateway, `+kestrel_find_part+` should return `+KI-CP-40817+`, and `+kestrel_check_stock+` at Denver should give quantity 3 and a lead time of 1 day. A made-up part number such as `+KI-XX-00000+` means the lookup broke between the two tools. An extra check of the seal kit is fine.

If `+kestrel_estimate_delivery+` isn't listed after you register it, wait a few seconds and run the registration cell again. If the first delivery run already used it, the tool was registered on an earlier attempt at this module. After registration, the delivery run should call `+kestrel_estimate_delivery+`, get `+transit_days: 1+`, and answer one day.
