== If the result differs

.Open this if your result doesn't match what the notebook expects. It lists likely causes.
[%collapsible]
====

Success is 6 PASS, 0 FAIL, 0 SKIP. A cell that finishes without an error doesn't mean its cases passed, so read each case's verdict and reason.

If `+m6+` shows SKIP, the agent wasn't offered the delivery tool. Run the gateway cell under _Start from module 7_ again and look for `+kestrel_estimate_delivery+` in its list. If it's missing, register it as that section describes, then run the regression set again.

If a case fails because its run was cut off, the model used up its allowance of 4,096 tokens for one model call before it finished its answer. The allowance counts the model's reasoning as well as its answer. Run the set again.

If `+m1+` or `+m3+` fails, check which model endpoint the agent calls: add a cell and run `+print(lab.endpoint())+`. It should start with `+qwen3-8b-b+`, the endpoint module 2 moved the agent to. If it doesn't, run the reset cell and the gateway cell again.

For any other FAIL, the reason says what the check didn't find. Open that case's trace from the table in step 2 to see what the agent did instead. For `+m5+`, the reason tells you whether SB-2024-102 wasn't retrieved at all, or was retrieved but left out of the answer.

If the regression cell's link says the evaluation run isn't available, read the run's last lines. If they say the evaluation wasn't recorded in MLflow, every result is still in the report. Run the set again once MLflow is reachable, before you compare runs.

If a rerun gives different results, check the endpoint as above, and check that `+gateway_url+` in `+config.toml+` still holds the gateway address. `+config.toml+` keeps its contents when the workbench restarts. The reset cell puts it back to module 7's start, and the gateway cell after it sets the address again.
