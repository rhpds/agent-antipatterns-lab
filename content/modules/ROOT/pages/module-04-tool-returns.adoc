== Learning objectives

* Implement a structured tool-error contract of category, retryable flag and detail so that failed tool calls surface instead of becoming confident empty answers.
* Analyze a trace to distinguish a tool that returned no data from a tool that failed to run.

== The success that is not one (3 min)

. Run the question. Portland is not a Kestrel depot.
+
[source,bash,role=execute]
----
python agent.py --q m4
----
. Note the answer: fluent, authoritative, and reporting no problem.

== Find the empty envelope (3 min)

. Open the trace: the tool was called, returned quickly, and the run ended cleanly on `stop`.
. Open the tool's actual return value:
+
[source,bash,role=execute]
----
python payloads.py
----
. Note it is `{"results": []}` with no sign of failure.
. Open `run_tool` in `tools.py`. It catches every exception and returns the same empty envelope. `check_stock` also drops a depot it does not recognise.

== Give failure a shape (6 min)

. Apply the supplied error contract:
+
[source,bash,role=execute]
----
cp solutions/module-04/tools.py solutions/module-04/agent.py .
----
. Read what changed:
.. Every tool return carries `category` (`ok`, `no_results`, `bad_request`, `upstream_unavailable`), `retryable`, and `detail`.
.. `check_stock` rejects an unknown depot as `bad_request`.
.. The loop passes a non-`ok` result back to the model as a result, not as data, and retries only when `retryable` is true, once.

== Re-run and see it surface (2 min)

. Re-run the Portland question:
+
[source,bash,role=execute]
----

+
[source,bash,role=execute]
----

----
. Run a question the data does cover, and confirm `ok` appears in the trace:
+
