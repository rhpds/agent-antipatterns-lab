The supplied agent also tells the model how to interpret the categories and to use returned part numbers for dependent stock checks. A structured tool error needs to be reflected in the answer.

Every tool return now carries a `+category+` (`+ok+`, `+no_results+`, `+bad_request+`, `+upstream_unavailable+`), whether a retry could help, and a detail the model can use. `+check_stock+` rejects an unknown depot as `+bad_request+`.

== If the result differs

If Portland still returns an empty `+results+` list without a category, confirm that both supplied files were copied after the reset. If the tool reports `+bad_request+` but the answer still says the part is out of stock at Portland, the lesson has not passed: the response must explain that the stock check could not be completed because the depot is unknown. Compare that with the valid Denver sensor query, whose `+no_results+` means actual lack of stock. Inspect the category and the answer together; neither a fluent answer nor a successful cell proves the contract was understood.
