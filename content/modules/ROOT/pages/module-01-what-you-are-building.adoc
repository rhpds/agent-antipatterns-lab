== 1. Meet the agent

The agent answers field service questions for Kestrel Industrial, a fictional maker of industrial cooling equipment. The lab folder in your workbench, `+agent-antipatterns-lab+`, has the two parts you'll use:

[source,text]
----
agent-antipatterns-lab/
├── notebooks/         the modules, one notebook each
└── agent/             the agent you'll fix
    ├── agent.py       the loop
    ├── tools.py       the tools the model is offered
    ├── config.toml    which model endpoint it calls
    └── runs/          the payloads each run saves
----

The first code cell above changed the working directory to `+agent/+`, so commands such as `+python agent.py+` run there. Click a file name to open it: link:{lab-source-url}/agent/agent.py[`+agent.py+`^], link:{lab-source-url}/agent/tools.py[`+tools.py+`^], link:{lab-source-url}/agent/config.toml[`+config.toml+`^].

Each run leaves two kinds of evidence: the raw payloads under `+agent/runs/+`, and a trace in MLflow.

== 4. Your first trace

MLflow keeps one *trace* per run. A trace is a tree of *spans*, one per step:

* `+agent_run+` is the whole run. Its outputs say how the run ended and how many tools it called.
* `+model_call_1+` is one request to the model. Its *Inputs* hold the messages and the tools offered; its *Outputs* hold `+finish_reason+`, `+tool_calls+` and `+content+`.
* A tool the agent actually runs gets its own span underneath. This run should have none.

Open the trace and click each span. Compare what it shows with the payload above.

== 5. The rule for the rest of the lab

The answer is a claim. The evidence is somewhere else. Every module from here on ends by checking the evidence: the payload in this module and the next, then the trace from module 3 on. In the trace, what matters is the number of turns, the order of tool calls and the error categories.
