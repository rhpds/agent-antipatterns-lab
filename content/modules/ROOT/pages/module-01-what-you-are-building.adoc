== If the result differs

.Open this if your result doesn't match what the notebook expects. It lists likely causes.
[%collapsible]
====

If the answer holds a real part number, or `+tool_calls (call 1)+` names a tool, the agent isn't on the endpoint module 1 starts on. Check that the endpoint cell printed `+qwen3-8b-a+`. If it didn't, run the reset cell at the top of the notebook again, then the cells after it.

If the agent cell ends in an error instead of an answer, such as a timeout or a connection error, it couldn't reach the model endpoint. That's a problem with the lab environment, not the failure this module shows. Wait a minute and run the cell again.

If the agent printed "No trace recorded: MLflow couldn't be reached", your payloads are still saved, so steps 2 and 3 still work, but the trace link says "not available yet". Run the agent cell again to get a trace.

The table, the `+content+` cell and the trace link only show runs made since the notebook's kernel started. If you restarted the kernel, or the workbench restarted, they say "No runs in this notebook yet", "No runs yet" or "not available yet", even though your earlier run is saved. Run the first code cell again, then the agent cell and the cells after it.
