== 2. A stronger prompt

Every request the agent sends starts with a *system prompt*: instructions the model reads before the question. The agent's is `+system_prompt+` in `+config.toml+`, and as the lab ships it, it says:

____
You are a field service parts assistant for Kestrel Industrial, a manufacturer of industrial process chillers (K-200, K-400, K-600). Help service engineers find the right part and check whether they can get it. Be concise.
____

The *stronger prompt* is `+system_prompt_strong+`: the same text with three sentences added that tell the model plainly to use its tools:

____
You MUST use the available tools to look up part numbers, stock and other facts. Never answer from memory. Always call a tool first.
____

`+python agent.py --strong-prompt+` sends that version instead. Nothing else in the request changes: the same question, the same tools, the same endpoint. Making the instructions more forceful is the first fix most people reach for when an agent won't use its tools.

The next cell shows the added sentences as they are in your `+config.toml+`, and the one after runs the agent with the stronger prompt.

=== What the tool-call parser does

Here is what sits between the request and the response inside one endpoint:

[mermaid]
....
flowchart LR
  A["agent.py"] -- "messages and tools" --> API
  subgraph E["One endpoint: a vLLM server"]
    API["OpenAI-compatible API, /v1/chat/completions"] --> CT["Chat template: messages and tool definitions become the text the model reads"]
    CT --> MOD["Qwen3-8B writes text, including any tool call"]
    MOD --> RP["Reasoning parser: moves the model's thinking into its own field"]
    RP --> TP{"Tool-call parser: does it recognise the call?"}
  end
  TP -- "yes" --> OK["tool_calls holds the call, finish_reason is tool_calls"]
  TP -- "no" --> NO["the call stays in content, tool_calls is null, finish_reason is stop"]
....

The *tool-call parser* reads the model's text and turns a tool call it recognises into `+tool_calls+`. On endpoint A it doesn't match this model's output, so it finds nothing and returns the text as an ordinary answer, with no error. Each stage is one argument on the ServingRuntime, as you just saw (`+--tool-call-parser+`, `+--reasoning-parser+` and the rest).
